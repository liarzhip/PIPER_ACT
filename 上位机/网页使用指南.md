# PiPER-X ACT 网页工作台

## 独立前端项目

上位机已迁至 D:\piper_act\上位机，不再放在数据采集目录。
先在 frontend 目录运行 npm ci 和 npm run build，再启动后端。开发流程见 README.md。

## 启动

在现有采集 Python 环境中运行（Python 3.10 或更新版本）：

```sh
python -m pip install -r requirements-web.txt
python web_app.py --dataset-dir ../Dataset/stand_bottle_rgbd
```

浏览器打开 http://127.0.0.1:5000 。首次启动会把 `--dataset-dir` 作为“默认任务”的数据目录；以后在任务窗口中新建的任务会自动创建独立的数据集与模型目录。

真实采集需在连接 PiPER-X 与 Orbbec DaBai DC1 的电脑上运行后端，沿用原有 `piper_sdk`、`pyorbbecsdk` 和 Linux SocketCAN 环境及 CAN 初始化操作。网页不会自动配置 CAN，也不会发送机械臂运动指令。Windows 上可以回放、验证或运行模拟演示。

页面顶部会自动读取本机 Conda 环境并检查 `piper_sdk`、`pyorbbecsdk`、`torch`、OpenCV 和 `h5py`。选择的环境会用于训练与执行子进程；真实采集要求网页后端本身也运行在该环境中。本项目机器应选择依赖完整的 `piper_act` 环境。

需要同一可信局域网内的另一台电脑访问时：

```sh
python web_app.py --host 0.0.0.0 --port 5000 --dataset-dir ../Dataset/stand_bottle_rgbd
```

然后访问 `http://采集电脑IP:5000`。服务无账户认证，不要暴露到公网；只运行一个服务进程，并避免原采集脚本同时占用相机或写入同一目录。

## 任务中心

- 点击左侧“当前任务”或右上角“切换任务”，可打开任务选择窗口。
- 新建任务只需输入名称；采集、训练、执行三个页面会一起切换到这个任务。
- 新任务文件夹会追加 6 位十六进制唯一后缀，例如 `Stand_bottle_94d505` 中的 `94d505`，用于避免同名目录冲突。任务窗口会直接显示文件夹名和后缀。
- 可在任务窗口同步重命名当前任务。任务名称、数据集文件夹、模型文件夹及内部路径会一起更新，原 6 位唯一后缀保持不变；任一步失败都会回滚。
- 任务卡片显示 Episode 数量和最佳模型状态，并根据进度提示下一步。
- 正在采集、训练或执行时禁止切换任务，避免把数据或模型写到错误目录。

## 数据采集

1. 选择真实设备，确认 CAN、相机分辨率和采样频率。相机高度 `0` 保留原脚本的自动选择行为。
2. 点击“连接并预览”，移动一次主臂，等待相机、主臂 action 和从臂 qpos 就绪。
3. 调整起始位置和腕部视角，点击“开始录制”。
4. 完成示教后点击“停止并保存”，或设置自动停止秒数。保存后可直接录制下一段，无需重新连接。
5. “断开”会结束当前记录、保存并释放设备。停止记录不等于停止机械臂运动。关闭网页也不会停止后台采集，可重新打开页面继续操作。

超过图像延迟阈值、无图像、无从臂反馈或主臂尚未初始化的样本不会写入；页面会显示丢弃计数。主臂静止时继续采用原脚本的 HOLD 行为。图像预览最高约 15 fps，独立于数据集采样频率。Windows 下网页直接调用原 RGB-D 采集实现，保存 RGB、对齐深度、qpos 和 action，可直接用于当前训练脚本。

录制中写入 `.hdf5.partial`，成功关闭后重命名为 `.hdf5`，编号自动递增，不覆盖已有文件。正常退出或设备异常会尝试保存已采集数据；异常中断会写入 `recording_error` 属性并在网页验证时提示。突然断电或强制结束进程仍可能遗留部分文件，网页不会将其列为完整 Episode。

## 模型训练

1. 选择已经采集至少两段 Episode 的任务。
2. 调整训练轮数、批量大小、动作块长度、KL 权重和学习率；模型维度等选项收在“模型与性能参数”中。
3. 点击“开始训练”。首次训练且数据目录没有 `depth_stats.json` 时，程序会先按训练集切分自动计算深度统计。
4. 页面每个 epoch 更新训练 Loss、L1、KL、训练进度和日志。鼠标移到曲线上可查看某个 epoch 的具体数值。
5. 最佳模型保存为当前任务模型目录中的 `policy_best.ckpt`。

## 任务执行

1. 默认选择“仅推理”，先检查相机画面、推理频率、图像延迟和日志，不向机械臂发送运动命令。
2. 需要真实运动时切换到“真实控制”。页面会显示安全检查，必须明确确认后才能启动。
3. 启动后网页调用现有 RGB-D 执行程序，并实时显示其相机叠加画面、推理耗时、推理/伺服频率和步数。
4. 点击“停止并保持当前位置”会通过停止文件通知执行程序走原有的安全退出与保持流程。物理急停始终应保持可用。

## 无硬件演示

选择“模拟演示”后连接、开始录制并保存。模拟数据写入当前任务数据目录下的 `demo/`，HDF5 属性 `sim=True`、`camera_backend=synthetic_demo`，页面有明显标识，不会计入正式任务的训练 Episode。

## 验证代码

```sh
python -m unittest discover -s tests -v
```

## 完整命令行参数

训练入口已切换至 train_piper_act_rgbd_global_v4.py，执行入口切换至 run_piper_act_windows_smooth_cpv_v6_rgbd_global.py。训练默认使用 100 轮、batch_size=10、chunk_size=20、sample_stride=10；执行默认 CPV CV=0.30、max_seconds=0（不限时），仍默认仅推理。其余参数可在各页面展开调整，旁边显示对应参数名称。采集新增深度范围、对齐、CAN 后端和可选 Episode 编号。数据及模型目录可用绝对路径覆盖，启动时更新当前任务目录，不移动已有文件。相机预览和开始/停止由网页替代原命令行交互。V6 新增网页接口但保持原命令行的运动确认、限速、超时与退出保持逻辑。

## 按文件夹识别与删除任务

任务列表会同步 Dataset 的直接子文件夹，忽略隐藏目录和目录链接；新发现的文件夹以文件夹名命名并对应 checkpoints 下同名模型目录。点击“刷新 Dataset 文件夹”或打开任务选择窗口可重新扫描。有效任务保留原 ID 和模型路径，已不存在的任务目录会从列表移除。

在任务选择窗口选择任务后，点击“删除当前任务及文件夹”，核对数据与模型绝对路径并输入任务名称确认。删除不可恢复，运行中的任务不能删除；共享目录、外部目录和链接目录不能自动删除。删除最后一个任务后显示空状态，可以重新创建任务，不会自动重建已删除文件夹。

## 训练启动修复

网页训练使用 training_entry.py 调用 train_piper_act_rgbd_global_v4_safe.py。未指定深度统计且数据集没有 depth_stats.json 时，自动按当前 seed、train_ratio 和 max_episodes 从训练集计算深度统计，缓存至数据集的 .depth_stats-cache 目录；验证集不参与统计。已有统计文件保留不覆盖。启动器和训练子进程补齐所选 Conda 环境的 DLL 搜索路径，避免 NumPy/Matplotlib 绘图阶段崩溃。

## V7 双相机适配

采集使用 piper_act_recorder_windows_dual_rgbd_v7.py；训练使用 train_piper_act_dual_rgbd_global_v7.py；执行使用 run_piper_act_windows_smooth_cpv_v7_dual_rgbd_global.py。腕部 Orbbec 与外部 RealSense 的宽高须一致，可分别设置帧率、深度范围及 RealSense 序列号。训练相机顺序固定 wrist external。缺少 depth_stats_dual.json 时按当前训练划分自动生成每路深度统计缓存。旧单相机数据仍可回看，不能直接用于 V7 双相机训练。回放验证入口统一跳转新版采集页面，双相机回放按左 wrist、右 external 拼接，验证增加帧龄及同步差检查。
